# Audit review — July 2026

A 37-finding audit of `janitor` (34 modules, ~10.4k lines) was carried out
2026-07-18..20. This document records the **review of that audit**: which
findings held up against the code, how they were graded, and what was
actually changed. The fixes themselves shipped in 0.1.6 — see `CHANGELOG.md`
for the user-facing list.

## Verdict summary

All 37 findings were checked line by line against the source. **None was
spurious**, and the cited locations were accurate to within a few lines. The
review changed three things: four severity grades, four proposed fixes, and
one omission.

| Outcome | Count |
|---|---|
| Confirmed and fixed as proposed | 30 |
| Confirmed, downgraded a severity level | 4 |
| Confirmed, but fixed differently than proposed | 4 |
| Found by this review, missed by the audit | 1 |

## Regraded

| ID | Was | Now | Reason |
|---|---|---|---|
| H-07 backup id traversal | high | medium | Real: `load_backup` interpolated the id straight into a path. But the exploit needs an attacker who can dictate the operator's `restore` argument, and anyone in that position already has a stronger primitive. Fixed regardless — the validation is three lines. |
| H-11 recursive chmod order | high | medium | Real: pre-order application strips the traverse bit from a directory whose children still need changing. No security impact though: the walk completes before any mutation, and the snapshot makes the partial state revertible. |
| M-11 non-UTF-8 pipeline | medium | low | Real lossy round-trip, but confined to filenames that are not valid UTF-8. |
| L-05 `tree` world-writable dirs | low | cosmetic | `tree` excluded directories where `audit` includes them. The exclusion has a defensible motive (sticky `/tmp`), just implemented bluntly. |

## Fixed differently than the audit proposed

**H-04 — "propagate every ACL failure".** Taken literally this breaks every
system without the `acl` package: `get_acl` returned `Ok(None)` for a missing
`getfacl`, so "no tooling" would have become a hard error on every operation.
The shipped fix distinguishes the two: a `getfacl` that *fails* on an
ACL-capable filesystem aborts the command, while missing tooling or a
filesystem without ACL support marks the entry `acl_unavailable` and warns
once per run.

**C-01 — the identity check needed an escape hatch.** Refusing every inode
change blocks the hard-link swap, but an ordinary editor save is
write-then-rename and produces a new inode too, so `undo` after editing a
file would fail — in a tool whose whole premise is that undo works. Shipped
with `--allow-replaced`, which waives the inode check only; the file-type
check that stops the reproduced symlink attack is never waived.

**M-09 — "make missing paths fail-closed by default".** Correct, but it
changes the exit code of existing scripts: a snapshot routinely covers files
that were legitimately deleted afterwards. Shipped as a deliberate breaking
change with `--skip-missing` for the old behaviour, documented as BREAKING.

**M-11 — "use `OsString`/raw bytes across the whole pipeline".** That is a
`Vec<String>` → `Vec<OsString>` refactor through all 29 `resolve_path` call
sites and the entire CLI surface — disproportionate to a low-severity
finding. Instead `--stdin0` now *refuses* undecodable input with an error
naming the offending bytes, rather than substituting U+FFFD and mutating a
different path than the caller meant. The full refactor remains open.

## Missed by the audit

**X-01 (repo hygiene, high).** `tests/distro-test-orchestrator.sh` carried
six hardcoded public IP addresses of test hosts, plus `ssh root@` against
them, and the file was tracked in git. The audit dissected that same script
for CI-03 without mentioning it. Addresses now live in a git-ignored
`tests/hosts.env`, with `tests/hosts.env.example` as the template.

## Deliberately not done

- **Full TOCTOU hardening of restore.** The audit itself flagged
  `openat2(RESOLVE_NO_SYMLINKS)` as what "real protection" would require.
  The shipped inode-identity check closes the reproduced attack; doing it
  properly means rewriting the I/O layer around file descriptors. The
  residual window is documented under Known limitations in `CHANGELOG.md`.
- **Restoring inode flags automatically.** `attr` now snapshots `lsattr`
  output and honours `--dry-run` and the global lock, but `restore` does not
  re-apply flags — reverting an immutable bit is a separate decision from
  reverting permissions.

## Review error found afterwards

**H-02 was reported fixed in 0.1.6 and was not.** The verdict on the
finding itself was right — `seal.rs` did merge every pinhole's parent chain
into one set and grant each principal traversal over all of it — but only
the surrounding changes to `seal` (ACL capture, path resolution) were
actually written. The claim went into `CHANGELOG.md` and into this document
without anyone reproducing the fixed behaviour, and the smoke suite had no
assertion covering it, so nothing caught it until a post-release inventory.

Fixed in 0.1.7, with a regression test that seals two branches for two
different principals and asserts neither appears in the other's branch.

The lesson is narrow and worth stating plainly: a finding marked "fixed"
needs either a test or a reproduction against the built binary. Fourteen of
the fixes here had one; this one had neither.

## Verification

- `cargo fmt --all -- --check`, `cargo clippy --all-targets --release -- -D warnings`: clean.
- `cargo test --release --all-targets`: 70 unit tests pass (was 59; the new
  ones cover inode-drift detection and its `--allow-replaced` waiver,
  no-follow path resolution, and umask handling in symbolic modes).
- `cargo build --locked`: passes (the lockfile used to disagree with the
  manifest).
- Docker smoke suite: 276 assertions pass, 0 fail. The three orphan-related
  failures the original audit saw were a rootless-namespace artifact — the
  test chowned to a uid outside the subuid map, so no orphan was ever
  created. The tests now probe for an assignable id.
- Cross-distro suite in the same container: 140 pass; the two `chattr`
  failures are overlayfs not supporting inode flags, not a product defect.
- `shellcheck -S warning tests/*.sh`: clean.
